# Заявки в Telegram

Формы сайта отправляют заявку на `/api/lead`. Этот адрес обслуживает
`worker.js` — Cloudflare Worker, который пересылает заявку в ваш чат
в Telegram.

Сайт развёрнут как **Worker со статическими файлами**, а не как Cloudflare
Pages: в панели Cloudflare мастер «Create app» теперь создаёт именно Worker,
Pages постепенно выводится из обращения. Настройки в `wrangler.jsonc`, и
`run_worker_first` там направляет в скрипт только `/api/*` — остальные
страницы отдаются напрямую, без его участия.

## Почему через функцию, а не напрямую из браузера

Телеграм-боту нужен токен. Если дёргать API Telegram прямо со страницы, токен
окажется в исходном коде сайта, и его увидит любой, кто нажмёт «просмотр кода».
Дальше посторонний человек управляет вашим ботом: читает все заявки, пишет от
вашего имени, меняет настройки.

Поэтому токен живёт только в переменных окружения Cloudflare. В репозитории
его нет и быть не должно.

## Настройка, один раз

### 1. Создать бота

1. Откройте в Telegram диалог с **@BotFather**.
2. Отправьте `/newbot`.
3. Придумайте имя (видит человек) и username (обязан заканчиваться на `bot`).
4. BotFather пришлёт строку вида `1234567890:AAF...` — это **токен**.

Токен никому не пересылайте и не вставляйте в переписку. Если он утёк —
`/revoke` у BotFather выдаст новый.

### 2. Создать чат для заявок

1. Создайте группу в Telegram, например «Ironvane — заявки».
2. Добавьте туда своего бота и людей, которые будут разбирать заявки.

### 3. Узнать ID чата

1. Напишите в группе любое сообщение.
2. Откройте в браузере, подставив свой токен:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. Найдите в ответе `"chat":{"id":-1001234567890`. Число вместе с минусом —
   это **ID чата**. У групп он всегда отрицательный.

Если ответ пустой — удалите бота из группы и добавьте заново, затем обновите
страницу: событие о добавлении тоже содержит ID.

### 4. Вписать в Cloudflare

В панели Cloudflare откройте свой проект → **Settings** → раздел с
переменными (**Variables and Secrets**). Добавьте две, тип **Secret**:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
| `TELEGRAM_CHAT_ID` | ID из шага 3, вместе с минусом |

Тип **Secret**, а не Text: секрет после сохранения не показывается обратно
даже вам, и его не видно в логах сборки.

После сохранения запустите деплой заново — переменные подхватываются при
следующем развёртывании, а не сразу.

### 5. Проверить

Отправьте заявку с сайта. В группе появится сообщение. Если нет — откройте
логи Worker в панели (**Logs** / **Real-time logs**): скрипт пишет туда
причину отказа, например что переменная не задана. Сам токен он не пишет
никогда.

## Что приходит в чат

- Тип заявки: компания или частное лицо
- Имя, email, Telegram
- Поля, относящиеся к выбранному режиму
- Тариф — если заявка со страницы подписок
- Страница, с которой отправлено, и код страны по IP

Подписка на материалы приходит с заголовком «Подписка на материалы», чтобы её
не путать с заявкой на проект.

## Ограничения, заложенные в функцию

- Принимается только POST и только с этого же домена.
- Тело больше 12 КБ отклоняется, каждое поле обрезается до 2000 символов.
- Ловушка для ботов проверяется на сервере, а не только в браузере: бот,
  который постит напрямую в `/api/lead`, скрипт страницы не выполняет.
  Заполненная ловушка получает обычный ответ «принято» и никуда не пересылается —
  сообщать боту об ошибке значит учить его обходить проверку.
- Обязателен только корректный email: форма подписки на материалы состоит из
  одного поля, и требовать там имя значило бы отклонять каждую подписку.

## Если хостинг сменится

Скрипт написан под Cloudflare Workers (`worker.js`, экспорт по умолчанию с
методом `fetch`). Логика внутри переносимая — меняется только обёртка:
у Netlify это `netlify/functions/lead.js`, у Vercel `api/lead.js` с другой
сигнатурой. Для хостинга без функций вообще нужен посредник: свой скрипт на
сервере или сторонний сервис форм.

Ни при каком варианте токен не должен попадать в файлы сайта.
