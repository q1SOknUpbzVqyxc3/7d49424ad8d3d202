# Цвет: где он лежит и как его вернуть назад

Обновлено 23.08.2026. Цвет одобрен владельцем в этот день.

## Коротко

Весь цвет добавлен **тремя блоками в конец одного файла** —
`assets/css/main.css`, строки 5227–5429. Больше нигде правок оформления нет.
Всё остальное, что вы видите в этих трёх коммитах — по две строки в 161
HTML-файле, — это не цвет, а метка версии (см. ниже).

## Три блока

| Блок | Строки | Что делает |
|---|---|---|
| Секция 28 «Colour that carries meaning» | 5227–5288 | Тонкая цветная черта над плитками с цифрами в кейсах |
| Секция 29 «A colour per vertical» | 5289–5362 | Свой цвет каждой из шести вертикалей |
| Секция 30 «More light» | 5363–5429 | Больше света: свечение панелей, пятно за курсором, подсветка внутренних страниц |

Каждый блок начинается комментарием, где написано, зачем он и что
сознательно **не** делает. Это не украшение текста: без объяснения часть
решений выглядит как недоделка. Например, в секции 28 цифры намеренно
оставлены белыми — 580 из 645 плиток помечены как рост, и если покрасить
сами числа, зелёным станет почти весь сайт, после чего зелёный перестанет
что-либо значить.

## Про «гамму»

Гамму никто не трогал — такой настройки в вебе нет. То, что выглядит как
«подняли яркость», сделано в секции 30 и касается только прозрачности
световых слоёв:

- свечение панели — было 0.10, стало 0.17
- подсветка карточки — было 0.055, стало 0.09
- пятно за курсором в шапке главной — было 0.13, стало 0.19

Плюс появилась подсветка вверху внутренних страниц, которой раньше не было
вовсе: до этого все страницы, кроме главной, открывались на плоском чёрном.
Именно это, а не палитра, делало их суше главной.

Ни один цвет здесь не менялся — менялась только сила света.

## Почему в коммитах правится 161 HTML-файл

В каждой странице стоит ссылка на стили с меткой версии:

```
<link rel="stylesheet" href="../../assets/css/main.css?v=50cd41de">
```

Браузер посетителя держит стили в кеше. Если метку не менять, человек,
заходивший на сайт раньше, увидит старое оформление и решит, что деплой не
прошёл. Меняется метка — браузер забирает файл заново. Это одна и та же
правка, размноженная по всем страницам, а не 161 разное изменение.

## Точки восстановления

В репозитории расставлены именованные метки. Посмотреть их:

```bash
git tag -n1
```

| Метка | Куда возвращает |
|---|---|
| `colour-before` | как было до цвета — монохромный сайт |
| `colour-tones` | только шаг 1 |
| `colour-verticals` | шаги 1–2 |
| `colour-light` | шаги 1–3 |
| `colour-approved` | одобренное состояние (текущее) |

### Убрать один шаг, оставив остальные

Каждый из трёх коммитов снимается отдельно, не задевая два других — блоки
для того и разложены по разным секциям:

```bash
git revert 0faa4c7
```

Вместо `0faa4c7` подставьте нужный: `fe02977` — тон на метриках,
`efea76c` — цвета вертикалей, `0faa4c7` — свет.

Это не стирает историю: сверху ложится новый коммит, который отменяет
старый. Передумаете — отменяется так же.

После любого отката метку версии в HTML нужно сменить, иначе вернувшиеся
посетители увидят кеш.

### Вернуть всё как было до цвета

```bash
git revert --no-commit colour-before..colour-light
```

## Известная мелочь

Номера секций 28, 29 и 30 в `main.css` заняты дважды: те же номера уже стояли
у блоков на строках 3972, 3986 и 4075. На работу сайта это не влияет —
номера живут в комментариях. Правится переименованием новых в 31, 32, 33.
